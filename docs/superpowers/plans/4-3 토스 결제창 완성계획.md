# 4-3 토스 결제창 완성 계획 (표준 결제창 통합 연동)

본 계획서는 FittersSweat 이커머스 체크아웃(`/checkout`)의 결제 수단 인터페이스를 토스페이먼츠 SDK v2 표준 결제창(`payment()`) 방식으로 전환하고, 사용자 지정 브랜드 에셋(`docs/image.png`)을 활용하여 Dark Athletic 디자인 시스템에 부합하는 완성도 높은 단일 결제 카드 UI를 구축하는 구현 명세서입니다.

---

## 1. 개요 및 배경

* **문제 상황**: 토스페이먼츠 SDK v2에서 API 개별 연동 키(`test_ck_...`)로 결제위젯(`widgets()`)을 초기화할 경우 `NotSupportedAPIIndividualKeyError` 예외가 발생하여 위젯 렌더링이 차단됨.
* **채택된 솔루션 (방안 1)**: 
  * 위젯 방식의 복잡한 iframe 주입 및 키 제약을 배제하고, 보유 중인 `test_ck_` 키를 100% 네이티브로 지원하는 **토스페이먼츠 표준 결제창(`payment()`) 통합 단일 카드** 방식을 채택.
  * `docs/image.png` 토스페이먼츠 공식 로고를 정제하여 결제 수단 카드에 적용.
  * 쇼핑몰 자체 필수 결제/이용 동의 체크박스 완비.

---

## 2. 핵심 스킬 훅 & 설계 원칙

### 1) Ponytail Hook (Senior Lazy Dev / YAGNI)
* **Ladder Level: Full** (최소한의 코드로 완벽한 동작 보장)
  * **불필요한 코드 대거 삭제**: 기존 위젯 로딩 상태(`isWidgetLoading`), 위젯 에러 폴백 배너(`widgetError`), DOM 정리 코드(`replaceChildren()`), 빈 iframe 컨테이너(`#payment-method`, `#agreement`) 완전 제거.
  * **네이티브 SDK 활용**: 이미 설치된 `@tosspayments/tosspayments-sdk`의 `tossPayments.payment({ customerKey })`를 그대로 호출.
  * **Shortest Path**: [결제하기] 클릭 시 단 한 줄의 `payment.requestPayment({ method: 'CARD', ... })` 호출로 국내 모든 카드사 + 간편결제(토스페이/카카오페이/네이버페이) 오버레이를 즉시 실행.
  * **Ponytail 원칙**: `[code] → skipped: [위젯 iframe 라이프사이클 관리], add when [위젯 전용 test_gck_ 키 도입 시].`

### 2) UI/UX Pro Max (Dark Athletic Design & Accessibility)
* **결제 수단 카드 디자인**:
  * 배경: `#141414`, 보더: `#262626` (기본) -> 선택 시 보더: `#FFD700` (Gold Accent) 및 은은한 골드 글로우.
  * **토스페이먼츠 브랜드 로고 뱃지**: `docs/image.png`를 `frontend/public/images/toss-payments.png`로 배치. 다크 모드 배경에서 로고의 파란색 3D 심볼과 텍스트가 왜곡 없이 최상의 시인성을 갖도록 화이트 캡슐 뱃지(`bg-white px-2.5 py-1 rounded-md`) 컨테이너로 감싸서 배치.
  * 지원 수단 안내 칩: `신용·체크카드`, `토스페이`, `카카오페이`, `네이버페이` 등 지원 수단을 미니멀한 뱃지(`bg-neutral-800 text-neutral-300 text-xs px-2 py-0.5 rounded`)로 시각화.
* **약관 동의 섹션**:
  * `[v] 주문 상품 및 결제 조건 확인 및 결제 진행 동의 (필수)`
  * `[v] 개인정보 제3자(토스페이먼츠) 제공 동의 (필수)`
  * 전체 동의 체크박스 제공 (1탭으로 두 항목 동시 토글).
  * 모든 체크박스는 44px 이상 터치 타겟과 명확한 `<label htmlFor="...">` 바인딩 적용.
* **CTA 결제 버튼**:
  * 높이 56px, 골드 테마 (`bg-[#FFD700] hover:bg-[#FACC15] text-black font-black text-base active:scale-[0.99]`).
  * 약관 미동의 시 부드러운 유효성 안내 및 비활성화/에러 스크롤 연동.

### 3) Superpowers Process
* 사용자 확인 전 무단 코드 변경 금지 원칙 준수.
* 단계별 계획 수립 -> 승인 획득 -> 구현 -> 브라우저 E2E 검증 (Chrome Control).

## 4. 구현 세부 태스크 (Task Breakdown)

### Step 1: 브랜드 에셋 준비 및 최적화
* `docs/image.png`를 `frontend/public/images/toss-payments.png` 경로로 복사.
* Next.js 정적 에셋 서빙 경로 확인 및 이미지 비율(3:1) 최적화 스타일링 준비.

### Step 2: 결제 페이지(`frontend/app/checkout/page.tsx`) 상태 및 UI 개편
1. **상태 관리 단순화 (Ponytail)**:
   - 불필요한 상태 제거: `widgetsRef`, `isWidgetLoading`, `widgetError` 제거.
   - 신규 상태 추가:
     ```typescript
     const [agreedTerms, setAgreedTerms] = useState({
       all: false,
       service: false,
       privacy: false,
     });
     ```
2. **결제 수단 단일 카드 렌더링**:
   - 골드 테두리(`border-[#FFD700] bg-[#141414]`)와 라디오 체크 아이콘.
   - Toss Payments 로고 뱃지(`next/image` 또는 `img` 태그, `h-7`, `bg-white px-2.5 py-1 rounded-md`).
   - 지원 수단 태그 알약(Pill) 배치.
3. **주문 및 결제 동의 섹션 렌더링**:
   - '전체 동의' 및 '개별 필수 2건' 체크박스.
   - 미동의 상태에서 [결제하기] 클릭 시 해당 영역으로 스무스 스크롤 및 붉은 보더/경고 피드백.

### Step 3: 결제 실행 함수(`handlePayment`) 표준 결제창 전환
* `tossPayments.payment({ customerKey: ANONYMOUS })` 인스턴스 생성.
* `payment.requestPayment({ ... })` 실행:
  ```typescript
  const tossPayments = await loadTossPayments(TOSS_CLIENT_KEY);
  const payment = tossPayments.payment({ customerKey: ANONYMOUS });

  await payment.requestPayment({
    method: 'CARD', // 모든 국내외 카드 및 토스페이/카카오페이 통합 제공
    amount: {
      currency: 'KRW',
      value: totalAmount,
    },
    orderId,
    orderName,
    successUrl: `${window.location.origin}/checkout/success`,
    failUrl: `${window.location.origin}/checkout/fail?amount=${totalAmount}`,
    customerEmail: form.ordererEmail,
    customerName: form.ordererName,
  });
  ```
* 결제 취소/창 닫기 발생 시: 기존과 동일하게 재고 롤백을 위해 `router.push('/checkout/fail?orderId=...')` 안전 처리 유지.

### Step 4: 레거시 위젯 DOM 및 오류 배너 제거 (Code Cleanup)
* `#payment-method`, `#agreement` 컨테이너 및 복잡한 `useEffect` 위젯 마운트 로직 완전 삭제.
* 위젯 오류 배너 및 모의 결제 유도 문구 정리.
