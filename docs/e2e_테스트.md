# FittersSweat E2E 시나리오 기반 UX & 기능 검증 명세서 (E2E Test Specifications)

> **문서 버전**: 1.0.0  
> **검증 대상**: Next.js 14 프론트엔드 + Fastify 4 REST API + PostgreSQL (pgvector) + Toss Payments + Cloudinary CDN  
> **검증 목적**: 실제 서비스 환경에서 HYROX 레이서 사용자의 관점으로 의도대로 동작하는지, UX 인터랙션과 기능 안정성을 종합 검증

---

## 1. E2E 테스트 개요 및 검증 원칙

본 문서는 단위/통합 테스트를 넘어, **"실제 사용자가 브라우저에서 마주하는 흐름 그대로"** 시스템 전체의 정합성을 검증하기 위한 시나리오 기반 E2E 명세서입니다.

### 핵심 검증 관점
1. **사용자 여정 연속성 (User Journey Flow)**: 대회 탐색부터 장비 구매, 결제, 커뮤니티 후기 작성까지 단절 없는 완결된 플로우 확인.
2. **UX 피드백 & 모션 정합성 (Feedback & Motion Fidelity)**: `디자인_가이드라인.md`에 정의된 마이크로 인터랙션과 하이브리드 모션이 의도대로 동작하여 사용자의 인지 부하를 줄여주는지 검증.
3. **데이터 및 트랜잭션 무결성 (Data Integrity)**: 장바구니 조작, Toss Payments 결제 승인/롤백, 재고 선차감, 게시글-상품 외래키 태깅이 DB에 정확히 반영되는지 확인.

### 시나리오 1: HYROX 대회 탐색 및 관심 등록 (Event Exploration & Bookmark)

* **테스트 목표**: 레이서가 다가오는 대회를 탐색하고, 관심 대회를 북마크하여 마이페이지에서 추적할 수 있는지 검증.
* **사전 조건**:
  - 백엔드 서버(`localhost:3001`) 및 프론트엔드(`localhost:3000`) 정상 구동
  - DB에 2026 서울, 송도, 부산 등 최소 3개 이상의 HYROX 대회 데이터 존재

#### Step-by-Step 사용자 행동 및 검증 기준

| 단계 | 사용자 액션 (Action) | 시스템 및 UX 반응 (Expected UX & Motion) | 백엔드 및 데이터 검증 (Verification) |
| :---: | :--- | :--- | :--- |
| **1-1** | 브라우저에서 `/events` 페이지 접속 | • 상단 네비바의 `대회 일정` 링크에 골드 언더라인 활성화<br>• 대회 카드 리스트가 다크 테마 그리드로 렌더링 | `GET /api/v1/events`<br>HTTP 200 응답 확인 |
| **1-2** | '2026 HYROX 서울' 대회 카드에 마우스 호버 | • 카드가 미세 스케일업(`scale-[1.02]`)되며 보더 점등<br>• 커서 포인터 즉시 변경 | CSS Transition 200ms 정상 발동 확인 |
| **1-3** | 카드 내 '관심 대회(하트)' 아이콘 클릭 | • 하트 아이콘이 빈 윤곽선에서 채워진 골드 하트(`text-[#FFD700]`)로 즉시 토글<br>• 미세 팝 애니메이션(150ms) 피드백 제공 | `POST /api/v1/events/:id/interested`<br>HTTP 200 응답 및 DB `InterestedEvent` 레코드 생성 확인 |
| **1-4** | 상단 네비바의 `마이페이지` 링크 클릭 | • `/mypage`로 매끄럽게 라우팅<br>• '관심 대회' 탭에 방금 등록한 '2026 HYROX 서울' 카드가 정상 노출 | `GET /api/v1/events/interested` 조회 및 카드 렌더링 일치 확인 |

#### 엣지 케이스 및 예외 처리
- **네트워크 지연 시**: 하트 버튼 클릭 시 낙관적 업데이트(Optimistic Update)로 UI가 즉시 반응해야 하며, 요청 실패 시 토스트 알림과 함께 이전 상태로 자동 롤백되어야 함.
- **연타 클릭 방지**: 버튼 연속 5회 클릭 시에도 `isSubmitting` 방어로 백엔드에 1회만 유효 처리되어야 함.

### 시나리오 2: 400개 카탈로그 탐색, 필터링 및 상세 조회 (Catalog Browsing & Motion UX)

* **테스트 목표**: 400개 직매입 장비 카탈로그를 카테고리/검색/정렬로 신속히 탐색하고, 레이아웃 깨짐 없이 상세 스펙을 확인할 수 있는지 검증.
* **사전 조건**:
  - 상품 400개 DB 적재 완료 및 Cloudinary CDN 이미지 URL 유효
  - Next.js `next.config.mjs`에 Cloudinary 도메인 등록 완료

#### Step-by-Step 사용자 행동 및 검증 기준

| 단계 | 사용자 액션 (Action) | 시스템 및 UX 반응 (Expected UX & Motion) | 백엔드 및 데이터 검증 (Verification) |
| :---: | :--- | :--- | :--- |
| **2-1** | 상단 네비바의 `레이서 장비몰` 클릭 (`/products`) | • 400개 상품 중 첫 20개 상품 카드가 1:1 정사각 그리드로 렌더링<br>• 상단에 카테고리 칩(`ALL`, `SHOES`, `NUTRITION`, `GEAR`, `EQUIPMENT`) 배치 | `GET /api/v1/products?page=1&limit=20`<br>`total: 400` 확인 |
| **2-2** | 카테고리 칩 중 `EQUIPMENT` 클릭 | • 선택된 칩이 골드 배경으로 반전<br>• **Framer Motion `layout` 발동**: 화면 깜빡임 없이 기존 카드가 부드럽게 재배치되며 스테이션 장비 리스트 노출 | `GET /api/v1/products?category=equipment&page=1` 호출 확인 |
| **2-3** | 검색창에 '슬레드' 입력 | • 300ms 디바운스 후 슬레드 관련 장비만 필터링되어 화면 갱신<br>• 검색 결과 개수("총 12개 장비") 정확히 표시 | 쿼리 파라미터 `search=슬레드` 반영 확인 |
| **2-4** | 정렬 드롭다운에서 '낮은 가격순' 선택 | • 상품 리스트가 가격 오름차순으로 즉각 재정렬 | `GET /api/v1/products?...&sort=price_asc` 확인 |
| **2-5** | 첫 번째 상품 카드 클릭 | • `/products/[id]` 상세 페이지 진입<br>• 좌측 1:1 Cloudinary 고해상도 뷰어, 우측 가격/재고/수량 조절기 렌더링 | `GET /api/v1/products/:id`<br>HTTP 200 확인 |

#### 엣지 케이스 및 예외 처리
- **검색 결과 0건 시**: 빈 화면이 아닌 "‘xyz’에 대한 검색 결과가 없습니다" 전용 Empty State 일러스트와 [전체 상품 보기] 버튼 제공.
- **이미지 로딩 지연 시**: Skeleton Shimmer 박스가 1:1 비율을 유지하여 이미지 로드 전후 누적 레이아웃 이동(CLS) 0 유지.

### 시나리오 3: 장바구니 담기 및 Toss Payments 결제 플로우 (Cart & Checkout Flow)

* **테스트 목표**: 장바구니 담기, 수량 변경, 퇴장 모션 품목 삭제 후 Toss Payments를 통한 결제 승인 및 재고 차감 완결성 검증.
* **사전 조건**:
  - 테스트 계정 로그인 완료
  - 테스트 상품 재고 5개 이상 확보
  - Toss Payments 테스트 클라이언트 키 환경변수 세팅 완료

#### Step-by-Step 사용자 행동 및 검증 기준

| 단계 | 사용자 액션 (Action) | 시스템 및 UX 반응 (Expected UX & Motion) | 백엔드 및 데이터 검증 (Verification) |
| :---: | :--- | :--- | :--- |
| **3-1** | 상품 상세(`/products/[id]`)에서 수량 '2'로 변경 후 [장바구니 담기] 클릭 | • 우측 상단 네비바 장바구니 배지 숫자가 `0`에서 `2`로 증가하며 튀어오르는 펄스(Pulse) 애니메이션 작동<br>• 하단에 "장바구니에 담겼습니다" 확인 토스트 노출 | Zustand `useCartStore` 상태 동기화 및 `localStorage` 영속화 확인 |
| **3-2** | 상단 장바구니 아이콘 클릭 (`/cart`) | • 장바구니 품목 리스트, 썸네일, 소계, 총 결제 금액 카드 정상 렌더링 | 주문 총액 = (단가 × 2) + 배송비(0원) 일치 확인 |
| **3-3** | 다른 상품 1종 추가 후 장바구니에서 해당 품목의 [삭제] 아이콘 클릭 | • **Framer Motion `<AnimatePresence>` 발동**: 해당 품목 카드가 좌측으로 슬라이드아웃되며 투명해진 뒤 DOM에서 제거<br>• 아래 품목들이 빈자리로 부드럽게 슬라이드업 | 장바구니 스토어에서 해당 항목 완전 제거 및 총액 자동 재계산 |
| **3-4** | [주문서 작성 및 결제하기] 클릭 (`/checkout`) | • 주문자 배송지 입력 폼 렌더링<br>• Toss Payments 결제 위젯 정상 마운트 | `POST /api/v1/orders`<br>주문 생성(`status: PENDING`), DB 재고 선차감 트랜잭션 수행 |
| **3-5** | 배송지 입력 후 [토스페이로 결제하기] 클릭 | • Toss Payments 공식 테스트 결제창 팝업/오버레이 오픈<br>• 테스트 카드 승인 클릭 | 토스 SDK 콜백 수신 대기 |
| **3-6** | 결제 성공 후 리다이렉트 (`/checkout/success`) | • "결제가 안전하게 완료되었습니다!" 완료 영수증 화면 렌더링<br>• 주문 번호, 결제 금액, 결제 승인 시각 표시<br>• 상단 장바구니 뱃지 `0`으로 리셋 | 백엔드 `POST /api/v1/orders/:id/payment` 최종 승인 완료, 주문 상태 `PAID` 전환 |

#### 엣지 케이스 및 예외 처리
- **결제 중 사용자 취소 또는 잔액 부족 시**:
  - 토스 결제창 닫힘 ➔ `/checkout/fail`로 리다이렉트
  - 백엔드에서 선차감되었던 재고가 즉시 원복(Rollback)되어야 함.
  - 장바구니 아이템은 유지되어 사용자가 재시도할 수 있도록 지원.
- **품절 상품 결제 시도 시**: 주문 생성 단계에서 `INSUFFICIENT_STOCK` 에러 반환 및 사용자에게 알림 모달 노출.

### 시나리오 4: 커뮤니티 레이서 완주 후기 및 장비 태깅 (Community & Gear Tagging)

* **테스트 목표**: 레이서가 완주 후기 작성 시 자신이 사용한 직매입 장비를 태그하고, 다른 사용자가 해당 태그를 통해 쇼핑몰로 즉시 연계 구매할 수 있는지 검증.
* **사전 조건**:
  - 커뮤니티 시딩 데이터(Task 3-5) 기 적재 완료
  - 로그인된 사용자 권한 보유

#### Step-by-Step 사용자 행동 및 검증 기준

| 단계 | 사용자 액션 (Action) | 시스템 및 UX 반응 (Expected UX & Motion) | 백엔드 및 데이터 검증 (Verification) |
| :---: | :--- | :--- | :--- |
| **4-1** | 상단 네비바 `커뮤니티` 클릭 (`/community`) | • 레이서 후기 및 훈련팁 피드 렌더링<br>• 각 게시글 카드에 대회 태그, 작성자 완주 배지, 태그된 장비 칩 노출 | `GET /api/v1/posts?page=1` 호출 확인 |
| **4-2** | [완주 후기 작성하기] 클릭 (`/community/new`) | • 글작성 폼 렌더링 (대회 선택 드롭다운, 제목, 내용, 장비 태그 추가 섹션) | 필수 입력값 유효성 검사 준비 |
| **4-3** | [사용 장비 태그 추가] 버튼 클릭 | • 장비 검색 모달 팝업 오픈 (`AnimatePresence` 스케일 페이드인)<br>• 장비명 검색 후 1개 상품 선택 완료 | 모달 내 검색 API 연동 및 선택된 장비 태그 칩 생성 |
| **4-4** | 제목/본문 입력 후 [게시글 등록] 클릭 | • 등록 중 버튼에 로딩 스피너 작동<br>• 등록 완료 후 생성된 글 상세 페이지(`/community/[id]`)로 자동 이동 | `POST /api/v1/posts` 호출<br>`PostProductTag` 테이블에 상품 ID 정상 매핑 확인 |
| **4-5** | 게시글 상세에서 본문 하단에 표시된 태그 장비 카드 클릭 | • 해당 장비의 쇼핑몰 상세 페이지(`/products/[id]`)로 즉시 화면 이동 | 라우팅 정상 동작 및 상품 상세 렌더링 확인 |

#### 엣지 케이스 및 예외 처리
- **미입력 상태 등록 시**: 제목 또는 본문이 빈 채로 제출되면 해당 입력창 테두리가 붉은색(`border-[#EF4444]`)으로 변하며 인라인 에러 텍스트 표시.
- **글 작성 도중 페이지 이탈 시**: 브라우저 `beforeunload` 경고 모달로 작성 중인 데이터 유실 방지.

```markdown

- [ ] 스티키 네비바: 스크롤 시 배경 블러(backdrop-blur-md) 및 헤더 고정 유지
```

## 4. 결함 보고 및 디버깅 가이드 (Troubleshooting)

1. **Framer Motion Hydration Mismatch 발생 시**:
   - 증상: Next.js SSR 환경에서 서버 렌더링과 클라이언트 모션 태그 간 불일치 경고
   - 해결책: 모션 컴포넌트에 `"use client"` 지시어를 반드시 명시하고, 마운트 여부 플래그(`mounted`)로 첫 페인트를 보호.
2. **Toss Payments 위젯 미렌더링 발생 시**:
   - 증상: 결제창 호출 시 SDK 인스턴스 초기화 에러
   - 해결책: Client Key 환경변수(`NEXT_PUBLIC_TOSS_CLIENT_KEY`) 설정 상태 및 클라이언트 사이드 스크립트 로드 완료 시점 검증.
3. **Cloudinary 이미지 403 / 미로드 에러 발생 시**:
   - 증상: 이미지가 표시되지 않고 깨진 링크 엑박 노출
   - 해결책: `frontend/next.config.mjs`의 `images.remotePatterns`에 `res.cloudinary.com` 호스트 등록 여부 확인.
